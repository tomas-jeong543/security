# Toy OS — 진행 중

x86 부팅 과정과 보호 모드 실행 환경을 단계적으로 구현하는 Assembly 프로젝트입니다. 구현 과정과 QEMU 실행 검증 스크린샷을 [toy_os.docx](toy_os.docx)에 기록하며 개발을 이어가고 있습니다.

## 목표와 구현 범위

`boot11.asm`에는 BIOS를 이용한 섹터 로딩, GDT 설정, 보호 모드 전환, 스택 초기화, VGA 텍스트 출력 및 명령 문자열 검사 코드가 있습니다. 현재 진입 흐름에서는 고정된 문자열로 검사 함수를 호출합니다. 문서의 마지막 진행 기록은 IDT 엔트리 구조 학습과 등록 준비 단계입니다.

## 검증 기록

[toy_os.docx](toy_os.docx)에 단계별 실행 결과와 구현 설명을 함께 기록했습니다.

- 보호 모드 진입: GDT 설정과 모드 전환 후 VGA 메모리에 `K`를 출력한 QEMU 화면.
- 보호 모드 출력 함수: 화면 초기화 후 `Protected Mode!`와 `Press Command:`를 출력한 QEMU 화면.
- 이전 단계의 명령 처리: 입력 문자열과 `Unknown Command!` 응답을 보여주는 QEMU 화면.

각 화면은 해당 개발 단계의 검증 기록입니다. 이후 단계까지 모두 완성했다는 의미는 아니며, 현재는 IDT 구성과 인터럽트 처리 학습을 이어가고 있습니다.

## 자료 안내

- [boot11.asm](boot11.asm): 보호 모드 전환 이후 기능을 구현 중인 소스.
- `boot.asm`부터 `boot11.asm`: 단계별 소스. 버전별 변경점은 TODO.
- `.bin`, `.img`: 기존 바이너리와 부팅 이미지. 소스와의 일치 여부는 확인 필요.
- [toy_os.docx](toy_os.docx): 단계별 구현 과정, 학습 내용과 검증 스크린샷.
- [QEMU 실행 메모](QEMU_내용.txt): NASM 및 QEMU 명령 기록.

## 작성 범위와 결과

AI의 개념 설명·힌트와 TODO 형태의 코드 틀을 활용하고, 단계별 기능을 직접 구현·수정하면서 QEMU로 실행 결과를 검증했습니다. 문서에는 주소 계산 오류를 수정한 과정, GDT와 세그먼트의 의미, 스택 초기화, 기존 16비트 함수를 보호 모드에 맞게 변환한 과정을 기록했습니다. Assembly 소스와 생성된 바이너리·부팅 이미지는 구분해 보관합니다.

## 실행 환경

기존 메모는 NASM, QEMU 및 Windows CMD의 `copy /b`를 사용합니다. 프로젝트 폴더를 작업 디렉터리로 삼아 메모를 참고하십시오. 기존 실행 검증은 DOCX에 기록되어 있으며, 도구 버전 명시와 새 환경에서의 재현 절차 정리는 TODO입니다. 재빌드 시에는 기존 `.bin`과 `.img`를 덮어쓰지 않도록 별도 출력 경로를 사용하십시오.
