# EASILE 보안 회귀 검토

## 입력 자료

[루트 규칙](../../../AGENTS.md), 변경 diff, 대상 빌드 식별값, [보안 보존 설계](../../../docs/server-extension/security-preservation.md), [검증 계획](../../../docs/server-extension/validation-plan.md).

## 절차

1. 변경 전후 방어별 구현·프로젝트 포함·호출 위치·검사 주기·실패 처리를 대응시킨다. 존재와 활성은 별도 칸으로 기록한다.
2. CRC의 RVA·범위·기대값이 어느 EXE에 대응하는지 확인한다. 새 빌드나 테스트 EXE에 과거 값을 자동 적용하지 않는다. 값 변경으로 정상화하기 전에 독립 식별과 사람 검토가 필요하다.
3. `VerifyHeroIntegrity()`는 현 조사에서 호출이 발견되지 않았음을 출발점으로 삼는다. 호출을 새로 추가하는 것도 기능 변경이므로 승인 범위를 확인한다.
4. DLLGuard 원본 스캔이 호출되는지 확인한다. Dll2의 원본 스캔 생략 실행은 방어 활성 회귀 증거로 사용하지 않는다. 시스템 DLL 지연 로드 오탐과 실제 공격 모듈 탐지를 구분한다.
5. SpeedGuard의 220 고정 상한과 정상 MoveSpeed 업그레이드 관계를 검토한다. 검증 전 충돌을 확정 결함이나 해결 완료로 표현하지 않는다.
6. 궁극기의 CRC·서버 시간 규칙·기존 클라이언트 시간 규칙을 각각 추적한다. 서버 추가를 이유로 기존 방어를 제거하지 않는다.
7. 실행 승인이 있으면 정상 입력·실패 입력·재시작·정지·성장 등 관련 회귀를 수행한다. 문서 검토만 승인됐으면 실행하지 않고 남은 증거를 명시한다.

## 산출물

방어별 보존 표, 호출 근거, 실행 로그·종료 코드 또는 미실행 사유, 오탐·누락·빌드 의존 위험과 미해결 항목.

## 완료 기준

보존이 입증된 범위와 미검증 범위가 구분되고 임의 약화가 없어야 한다. 정적 호출 확인만으로 런타임 효과를 PASS 처리하지 않는다. 약화·삭제·새 예외가 필요하면 변경하지 않은 상태에서 근거와 검토안을 제시한다.
