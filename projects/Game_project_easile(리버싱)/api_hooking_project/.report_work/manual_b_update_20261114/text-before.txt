07  최종 Hook 대상 및 선정 이유
SpawnProjectile()은 direction만 바꿔 원본에 전달할 수 있어 최종 대상으로 선택했다.
기존 공격 EXE의 RVA는 0x137E0이다. 최종 Release의 SpawnProjectile은 RVA 0xF670이며 과거 주소·진입 바이트를 새 빌드에 승계하지 않는다.
기존 payload의 진입 14바이트 검사는 과거 EXE용이다. 새 EXE에서는 원본 payload가 설치를 거부했고, 해시가 고정된 별도 호환 DLL의 실제 E9 변조를 확인했다.
world는 this, Vec2는 float 2개(8바이트)다. 인자 순서와 크기를 원본 함수에 맞춘다.

13  방어 목표 / 위협 모델
기존 DLLGuard는 첫 렌더 후 DLL 목록을 baseline으로 저장하고 약 1초마다 새 경로를 비교한다. 허용되지 않은 DLL이면 경고창을 표시하고, 창이 닫히면 ExitProcess(1)로 종료한다. 로드 자체를 선제 차단하는 방식은 아니다.
기존 Dll2는 DetectNewModules(RVA 0xEF90)를 후킹하고 원본 스캔을 생략한다. 과거 재현에서 E9 변조와 SKIPPED 3회를 확인했다. 원본 스캔 활성이라는 설치 문구는 소스와 모순된다. 현재 C 시험에서는 설치 후 자체 종료 3이 먼저 발생해 SKIPPED는 0회다.

22  결과 해석 및 원인 분석
A의 경로 탐지와 C의 스캐너 코드 검사는 실제 GameClient에서 확인했다. B는 대상 함수 진입 전에 검사하므로 진입 detour 자체가 검사를 건너뛰지 못하도록 설계됐다.
BoundaryFixture는 동일 게임 소스를 사용하지만 Application의 A 주기 루프가 없다. 따라서 fixture 종료 2를 A/B/C가 함께 동작하는 실제 전투 결과로 확대할 수 없다.
B의 최종 판정은 실제 GameClient의 HK01_B 탐지 로그와 동일 PID의 자체 종료 2를 함께 확보할 때만 PASS다. 현재 종료 코드는 미수집이다.

23  한계 / 개선 방향
CRC32 추가 개선은 취소했으며 미적용이다. 현재는 정상 디스크를 전제로 함수 범위의 CRC32와 전체 바이트를 비교한다. 실행 전 EXE 코드가 바뀌면 변경된 디스크가 기준이 될 수 있다.
디스크 서명 신뢰, 검사 루틴 자체 변조, C 주기 사이 복원·스레드 중지, B의 검사/호출 경쟁, 함수 범위 밖 패치와 A baseline 누락은 남는다. 서버 확장·고정 profile·서명 도입은 이번 범위에 없다.

25  최종 메모
최종 상태: A 실게임 탐지 확인 / B 독립 시험 PASS·실게임 미검증 / C 실게임 탐지·자체 종료 3 확인.
수동 후속: 별도 실행 폴더에서 해시 확인된 Release 사본을 정상 실행하고 Enter로 시작한다. WASD로 전투에 접근해 Bot 발사 조건을 만든다. 원본·기존 로그는 덮어쓰지 않는다.
승인된 기존 관측 수단으로 같은 PID의 설치·B 탐지 로그·자체 종료 코드를 수집한다. 공격 재현이 제한되면 중단하며 A/C를 끄지 않는다. 투사체 로그와 영상의 관측 범위를 구분한다.
사람 검토: 실게임 B의 로그·종료 2 동시 확보, 각도 실측과 최종 투사체 연결, 장시간 오탐·성능은 남은 항목이다. 이번에는 정상 전투 입력을 수행하지 못해 B PASS를 선언하지 않는다.
