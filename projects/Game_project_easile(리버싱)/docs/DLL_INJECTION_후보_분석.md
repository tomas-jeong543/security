# EASILE DLL Injection 실험 후보 분석

분석 범위: 현재 저장소의 `src/`, `GameClient/GameClient.vcxproj`, `tests/GameTests.cpp`. 이번 문서는 후보 선정만 다루며 실행 파일과 게임 소스는 변경하지 않았다. 아래의 점수는 초심자의 첫 실험 적합도이며, 난이도 점수는 쉬울수록 높다.

## A. 현재 코드 구조 요약

- `src/main.cpp:4-7`의 `wWinMain`이 `Application::Run`을 호출한다.
- `src/Application.cpp:43-103`은 메시지를 처리하고, 입력을 읽은 뒤 0.01초 고정 간격으로 `GameWorld::Update`를 호출하며 스냅샷과 HUD를 그린다. `--smoke-gui`는 `Application.cpp:31-40`에서 별도 시뮬레이션을 먼저 진행한다.
- `src/InputManager.cpp:26-53`은 이동, LMB/K 기본 공격, J 궁극기 등의 입력을 `PlayerCommand`로 만든다. `src/PlayerController.h:6-15`는 사망 시 액션을 막고 이동·조준 방향을 정규화한다.
- `src/GameWorld.cpp:829-934`의 `GameWorld::Update`는 플레이어 이동·공격, 봇 AI, 투사체, 미니언, 타워, 회복 아이템 등을 순서대로 갱신한다. `src/GameWorld.h:92-116`이 영웅과 동적 게임 상태를 보유한다.
- `src/Hero.h:20-49,55-62`와 `src/Hero.cpp:4-38,51-70`은 HP, 피해량, 속도, 쿨타임, 재생과 업그레이드를 관리한다. `src/GameWorld.cpp:473-749`에는 봇 이동·공격·회복 판단이 있다.
- `src/CombatSystem.h:9-13`은 기본/궁극기 투사체의 속도와 최대 거리를 정하고, `src/GameWorld.cpp:198-262`가 이동·충돌·소멸을 처리한다.
- `src/GameWorld.cpp:936-1017`은 실제 상태를 렌더용 스냅샷과 `HUDViewModel`로 복사한다. `src/Renderer.cpp:69-130,271-342`는 게임 장면과 체력 막대를, `src/HUDRenderer.cpp:51-67,106-119`는 HP·피해량·쿨타임 텍스트를 표시한다.
- `src/Logger.h:10-17`은 `GameClient.log`에 시뮬레이션 시각과 이벤트를 추가 기록한다. 기본 공격의 `PROJECTILE_SPAWN` 로그에는 피해량이 들어간다(`src/GameWorld.cpp:132-143`).

**기존 방어와의 관계.** `GameWorld::Update`의 플레이어 궁극기 입력 분기에서만 `IntegrityGuard::VerifyUpdateIntegrity()`를 호출한다(`src/GameWorld.cpp:880-888`). 검사는 EXE의 고정 RVA·길이 바이트에 대해 CRC32를 계산하고 기대값과 비교한다(`src/IntegrityGuard.cpp:9-13,41-71`). 따라서 현재 코드가 모든 함수·DLL·데이터 변경을 검사한다고 볼 수 없으며, 실제 보호 바이트 범위는 현재 빌드에서 별도 확인이 필요하다. 같은 궁극기 분기에는 `simulationTime_ - lastUltimateUseTime_ >= 10`과 `UltimateReady()` 검사도 있다(`src/GameWorld.cpp:890-915`). HP나 이동 데이터 변경을 감지하는 별도 검사는 확인되지 않았다. CRC 실패 시 `Update`가 즉시 반환해 그 프레임의 나머지 갱신도 건너뛴다.

**실험 조건.** 프로젝트는 Debug/Release 모두 x64이고 Debug는 최적화가 꺼져 있으며 Release는 `MaxSpeed`다(`GameClient/GameClient.vcxproj:3-10,66-76`). 고정 RVA와 CRC는 빌드별 재검증 없이 공통으로 맞다고 가정할 수 없다. 재시작은 영웅과 투사체 등의 상태를 초기화한다(`src/GameWorld.cpp:48-88`). 화면 테스트는 포커스가 있어야 입력이 전달되고(`src/InputManager.cpp:26-29`), 실제 루프에는 고정 스텝과 프레임 시간 누적이 있으므로(`src/Application.cpp:55-95`) 같은 빌드·시작 상태·입력 순서·시뮬레이션 시간을 기준으로 비교해야 한다. 테스트는 내부 상태를 직접 검증할 수 있지만(`tests/GameTests.cpp:654-673,751-760`), 이 문서에서는 빌드와 실행을 하지 않았다.

DLL 로드만으로 게임 동작이 바뀌지는 않는다. 아래의 **데이터 변경**은 로드된 모듈이 게임 프로세스 안에서 실제 런타임 상태에 접근해야 한다는 개념이고, **함수 호출 개입**은 호출 지점의 동작을 바꾸는 별도 방식이다. **코드 패치**는 실행 바이트 변경 방식으로 이번 첫 실험에서는 우선하지 않는다. 현재 게임에는 실험용 공개 API가 없고 관련 멤버도 비공개이므로, 소스 수정 없는 데이터 후보도 실행 중 객체를 안전하게 식별하는 방법은 아직 검증되지 않았다. 숫자 주소·오프셋·호출 규약은 이 문서에서 지정하지 않는다.

## C. 최종 추천 TOP 3

### 1. 플레이어 현재 HP

- **이유·새 학습:** PATCH01의 실행 코드 변경 대신 프로세스 안의 런타임 데이터가 게임 로직과 HUD에 전달되는 과정을 확인할 수 있다. 근거는 `Hero::Health/Damage/Heal` 및 `hp_`(`src/Hero.h:20-21,41-43,55`), `GameWorld::CreateHud`(`src/GameWorld.cpp:996-1002`), `HUDRenderer::Paint`(`src/HUDRenderer.cpp:106-111`)다.
- **정상/변경 관찰:** 기본값은 100/100 HP(`src/Hero.h:55`)이고 피해를 받으면 HP가 줄어든다. 변경된 현재 HP가 유효 범위 안에서 반영되면 다음 HUD 갱신에 숫자와 막대가 함께 달라져야 한다. 성공 기준은 같은 피해·같은 시점에서 기준 실행과 다른 HP를 관찰하고, 표시값과 게임 내부 `Health()`가 일치하는 것이다.
- **실패·제약·복구:** 사망 중이거나 재시작 직후에는 상태가 덮일 수 있고, 회복은 최대 HP에서 상한 처리된다(`src/Hero.cpp:19-25`, `src/Hero.h:42`). 원본 객체 식별은 아직 확인되지 않았으며 임의 메모리 접근은 충돌 위험이 있다. 프로세스를 종료하고 새 게임을 시작해 초기 상태로 복구한다. 후속 방어 실험으로 HP 범위와 허용된 피해·회복 이벤트의 일관성을 검증할 수 있다.

### 2. 플레이어 이동 속도

- **이유·새 학습:** `Hero::Move`가 `speed_ * deltaSeconds`를 사용한다(`src/Hero.h:25,36-39,57`). `GameWorld::Update`는 이후 맵 충돌을 적용한다(`src/GameWorld.cpp:855-857`). PATCH01과 달리 매 프레임 사용되는 데이터가 위치 변화에 미치는 영향을 볼 수 있다.
- **정상/변경 관찰:** 기본 속도는 220 단위/초다. 직선의 장애물 없는 구간에서 1초 동안 일정 방향으로 움직일 때 기준 이동 거리는 이론상 약 220 단위이고, 속도 변경 시 그에 비례해 달라져야 한다. 성공 기준은 같은 100회의 0.01초 업데이트에서 위치 차이가 반복 실행 간 안정적으로 나타나는 것이다.
- **실패·제약·복구:** 맵 경계·벽·대각선 정규화·프레임 입력 차이가 측정을 흐린다. 화면의 카메라도 플레이어를 따라가므로 절대 위치 비교에는 내부 좌표 계측이 유리하다. 게임을 재시작하면 기본 영웅 객체로 복구된다(`src/GameWorld.cpp:48-53`). 후속 방어로 허용 이동량과 충돌 후 위치의 일관성을 확인할 수 있다.

### 3. 기본 공격 피해량

- **이유·새 학습:** 기본 공격은 `BasicDamage()`를 투사체 생성 인자로 전달한다(`src/GameWorld.cpp:867-876`); 생성 로그가 damage를 기록하고(`src/GameWorld.cpp:132-143`) 명중 시 대상 HP에 반영된다(`src/GameWorld.cpp:248-253`). PATCH01의 궁극기 검사를 건드리지 않고 발사 시점의 상태 복사를 관찰할 수 있다.
- **정상/변경 관찰:** 기본 피해량은 5이며(`src/Hero.h:56`), 대상에게 한 발이 명중하면 방어가 없는 영웅의 HP는 그만큼 감소한다(`src/CombatSystem.cpp:5-11`). 성공 기준은 `PROJECTILE_SPAWN`의 damage 값, HUD의 BasicDamage, 명중 대상 HP 차이가 같은 설정에서 일치하는 것이다.
- **실패·제약·복구:** 발사 뒤 영웅 피해량을 바꿔도 이미 생성된 투사체의 `damage`는 바뀌지 않는다(`src/Projectile.h:3`). 장애물·조준·타 공격의 명중을 통제해야 하며, 과도한 값은 경기 흐름을 크게 바꿀 수 있다. 재시작으로 기본 피해량이 복구된다(`src/GameWorld.cpp:48-53`). 후속 방어로 발사 로그·투사체 피해량·업그레이드 이력을 대조할 수 있다.

## D. 최종 1순위 결론

첫 DLL Injection 실험 후보는 **플레이어 현재 HP의 제한된 런타임 데이터 변화**다. 현재 HP는 게임 로직에 존재하고, `CreateHud`를 통해 숫자와 체력 막대로 즉시 확인할 수 있다. 기본 공격과 달리 명중 위치나 벽 조건을 맞출 필요가 없어 화면 관찰이 단순하다. 이동 속도보다 짧은 시간 안에 변화를 판정할 수 있으며, 재시작 시 객체가 초기화되어 복구 경로도 명확하다. 궁극기 코드 패치와 겹치지 않으면서 프로세스 내 상태 변경과 HUD 전달 과정을 배울 수 있다. 단, 현 코드에는 외부에 공개된 상태 변경 인터페이스가 없으므로 실제 실험 전에는 소스 변경 없는 객체 식별 가능성과 읽기·쓰기 시점의 안전성을 확인해야 한다. 그 확인이 어렵다면 별도 계측용 개발 빌드를 준비하는 방안이 필요하며, 이 문서 단계에서는 주소나 구현 방법을 단정하지 않는다.

**1순위 후보:** 플레이어 현재 HP의 제한된 런타임 데이터 변화.
**근거:** `Hero::hp_` → `GameWorld::CreateHud` → `HUDRenderer::Paint`가 연결되고, PATCH01 궁극기 경로와 구별된다.
**다음 실험 확인 사항:** 대상 객체 식별·안전한 관찰 시점·HUD와 실제 HP 일치 여부 및 빌드별 CRC 검사 영향.
