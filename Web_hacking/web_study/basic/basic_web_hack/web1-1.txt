프론트앤드: 사용자 요청 받는 부분 -> 웹 리소스로 구성됨
백엔드: 요청 처리 부분
웹 리소스 = 페이지 담기는 글, 글자들의 색깔과 모양,배경 색상,이미지의 크기나 투명도로
이는 웹에 갖춰진 정보 자산을 의미한다.

모든 웹 소스는 고유의 URI를 가지고 이를 이용해 식별이 된다.

프론트엔드의 경우엔 -> HTML, CSS, JS 등등 포함한다

HTTP는 request와 response로 정의한 프로토콜이다.
클라이언트 ->(요청)-> 서버 
클라이언트 <-(응답)<- 서버  구도임

웹 서버의 경우 HTTP서버를 HTTP 서비스 포트 TCP/80이나 TCP/8080에 대기시킴

 
80 -> HTTP , 22 -> SSH, 443 -> HTTPS가 할당됨
0 = 잘 알려진 포트 1023 = 특권 포트

HTTP 메시지 = 해더 + 바디로 구성이 된다

해더의 각 줄은 CRLF로 구분이 되고 첫 줄은 시작 줄, 나머지 줄은 해더라 부름 해더 끝은 빈줄로 나타낸다


헤더는 필드와 값으로 구성되며 HTTP메시지 혹은 바디의 속성을 나타낸다. 하나의 메시지에는 0개 이상의 헤더가 존재한다

바디는 헤더의 끝을 나타내는 CRLF 뒤의 모든 줄을 말한다.


CRLF = CR + LF의 조합이다.(윈도우 기준 이용) 리눅스 등 유닉스 기반에서는 LF만 이용함

HTTP요청
시작 줄은 메소드,요청 대상 그리고 http버전으로 구성되며 이를 띄어쓰기로 구분한다.

이 중에 메소드는 서버가 수행하길 바라는 동작으로 get,post등이 있다
GET은 리소스를 가져와달라 요청하는 메소드이고 POST는 요청 대상에게 데이터를 보내는
메소드로 그 예시로는 로그인할때 입력하는 ID,비밀번호 등이 POST로 서버에 보내진다.

요청 대상(URI)는 메소드의 대상은 HTTP버전은 클라이언트가 사용하는 HTTP프로토콜의 버전을 나타낸다.

HTTP응답

시작 줄은 HTTP버전, 상태 코드, 처리 사유로 구성이 되고 띄어쓰기로 구분이 된다

이 때 HTTP버전은 서버에서 사용하는 HTTP프로토콜의 버전을  알려주고
상태 코드는 요청에 대한 처리 결과를 세 자릿수로 나타낸다. -> 대략 40개 존재 + 첫 번째 자릿수에 따라 5개의 클래스로 분류가 된다.
처리 사유는 상태 코드가 발생한 이유를 짧게 기술한 것이다.


1XX -> 요청을 제대로 받았고 처리가 진행 중임
2XX -> 요청이 제대로 처리됨
3XX -> 요청을 처리하려면 클라이언트가 추가 동작을 해야 함
4XX -> 클라이언트가 잘못된 요청을 보내 처리 실패함
5XX -> 클라이언트의 요청은 유효하지만 서버에 에러가 발생해서 처리에 실패

HTTPS: 나온 이유 -> HTTP응답과 요청은 평문이라 가로채면 중요한 정보가 유출이 될 수 있기 때문이다.
HTTPS는 TLS를 도입해서 이 문제점을 보완한다. TLS는 서버와 클라이언트 사이에 오가는 모든 HTTP메시지를 암호화한다. 공격자가 중간에 메시지를 탈취하더라도 해석하는 것이 불가능하다 -> 도청과 변조로부터 보호가 된다.

TLS를 잘 이해하려면 TLS기반이 되는 공개 키 암호(PKCS) 시스템과 대칭 키 암호를 알아야 한다.
