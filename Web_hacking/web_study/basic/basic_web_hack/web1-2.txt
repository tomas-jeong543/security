웹 브라우저 -> 서버와 HTTP통신을 대신해주고 수신한 리소스를 시각화해서 웹의 시대를 만들었다

이용자가 DREAMHACK.IO입력시 브아우저 동작
1.주소창에 입력된 주소 해석(URL 분석)
2.  DREAMHACK.IO에 해당하는 주소를 탐색(DNS 요청)
3.HTTP통해  DREAMHACK.IO에 요청
4. DREAMHACK.IO의 HTTP응답 수신
5.리소스 다운로드 및 웹 렌더링

URL = 웹에 있는 리소스의 위치를 표현하는 문자열이다.
브라우저로 특정 웹 리소스로 접근시에는 URL을 사용해서 이를 서버에게 요청한다

예시
foo://example.com:8042/over/there?name=ferret#nose
\_/   \________________/\_________/ \____________/ \__/
 |            |              |             |         |
scheme     authority         path          query   fragment

scheme: 웹 서버와 어떤 프로토콜로 통신할 지 나타냄
authority-host: authority의 일부로 접속할 웹 서버의 주소에 대한 정보를 가짐
authority-port: authority의 일부로 접속할 웹 서버의 포트에 대한 정보를 가짐
path: 접근할 웹 서버의 리소스 경로로 '/'로 구분이 된다.          
query:웹 서버에 전달하는 파라미터이며 url에서 ? 뒤에 위치한다.
fragment: 메인 리소스에 존재하는 서브 리소스를 접근할 때 이를 식별하기 위한 정보를
담고 있으며 # 문자 뒤에 위치한다.


HOST => 웹 서버의 주소로  Domain name IP address의 값을 가질 수 있다

domain name을 host값으로 이용시에는 브라우저는 dns에 domain name을 질의하고 dns가
응답한 ip address를 사용한다.

domain name에 대한 정보는 nslookup명령어를 사용해서 확인을 할 수 있다.

웹 렌더링은 서버로부터 받은 리소스를 이용자에게 시각화하는 행위를 말한다
서버의 응답을 받은 웹 브라우저는 리소스의 타입을 확인하고 적절한 방식으로 이용자에게
전달한다. ex)서버로부터 html과 css를 받으면 브라우저는 html을 파싱하고 css를 적용해서 이용자에게 보여준다.


웹 렌더링은 웹 렌더링 엔진에 의해서 이루어지는데 브라우저별로 다른 엔진을 쓴다 사파리는 웹킷, 크롬은 블링크, 파이어폭스는 개코 엔진을 이용한다.(속도 순서의 차이는 있지만 본질은 같다)
